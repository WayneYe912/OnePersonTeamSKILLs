# 基于 PRD 设计测试用例

把需求规则和验收条件转成测试人员能准备、执行和判断的用例。按风险选择类型，不为凑数量批量改标题；用例生成、自动化脚本实现和实际测试执行是不同动作。

## 必须读取的资源

起草前完整读取 [用例设计与类型选型](references/test-design.md) 和 [用例契约与交接](references/case-contract.md)。使用脚本前读取源码或 `--help`。资源相对本技能目录定位，不绑定 Agent、编程栈或联网平台。

默认交付完整 `test-cases.json` 和易读的 `test-cases.md`，保留数据、步骤、断言、来源、覆盖缺口。[虚构 PRD](assets/example-prd.json)、[示例用例数据](assets/example-cases.json) 和 [完整用例示范](assets/测试用例示例.md) 展示字段粒度，不能替代用户材料。用户明确指定其他格式时借助宿主能力完成，不假称存在转换器。Python 3.9+ 标准库仅校验与排版，不代替 Agent 推导用例；无 Python 时按同样规范直接写文件。例子是虚构展示，不能作为真实 PRD 的替代品。

## 自动读取当前任务 PRD

1. 先检查用户明确指定、本轮已经验证的交接和同任务目录的 `pipeline.json`，完整读取实际 PRD、验收、附件及相关图表，沿用需求编号、版本与确认状态。不让用户重复发送已有材料。
2. 同仓库可完整读取 `../product-development/references/handoff.md` 并用 `../product-development/scripts/pipeline.py resolve --only-prd --task-dir <任务目录>`。此模式只要求 PRD，不要求技术方案或已有代码；旧技术方案或旧用例不妨碍基于新 PRD 重写用例。
3. 选择顺序为显式输入 > 本轮确定交接 > 同任务清单 > 同任务唯一约定名。多候选、版本变化、读不到或与来源冲突时先请用户确定，不按时间擅选，不跨任务扫描，更不能使用 `skills/*/assets/` 样例冒充用户输入。
4. 单独使用本技能时没有共享脚本仍可按同规则定位并读文档；自动化辅助缺失不等于只能交教程。远程文档由已授权的宿主能力读取，不能擅自上传或下载到未授权位置。

## 缺 PRD 时先询问并等待

完成有限只读检查后，没有可用 PRD 必须问：

> 当前没有找到可用的 PRD。是否要我先帮你完善 PRD，再基于它生成测试用例？也可以使用你已有的 PRD。

提问后等待用户回复，不擅自补文档、编业务规则或生成通用空模板。已有材料只缺有效路径时准确说明该缺口。提供选择可用“先帮我完善 PRD”和“使用已有 PRD”；若选已有，链接、路径或附件用自由输入获取，不把上传方式当选项。

- 用户同意：完整读取同仓库 `requirement-analysis/SKILL.md` 及必读资源，依据原话补齐 PRD、关键规则和验收，保存到同任务目录；只补缺失，不覆盖用户已有内容。文档缺关键对象或规则时继续必要澄清。
- 用户选择已有：请求可访问材料并读全，不自动重写。
- 用户拒绝：停止用例生成，说明最小输入；不能将拒绝视为无 PRD 生成许可。
- 前置技能不可用：说明能力缺口；未经授权不安装依赖或凭印象冒充其输出。

用户原本明确授权端到端先完善 PRD 时，不重复询问同一流程许可。补写许可不代表把新业务建议自动批准；不确定规则仍保留待确认，用例的预期必须同步保持待确认。

## 建立测试依据与覆盖范围

从 PRD 拆出可追溯测试条件（`AC-...`）：需求编号、原规则/验收、状态、来源位置、数据约束、权限角色、状态与异常、观察结果。上游已有验收编号直接保留；没有时分配稳定编号并记对应原句。

- 明确功能与非功能、本期与非本期，区分确认规则、设计建议、缺失口径，不把“体验流畅”编成数值 SLA。
- PRD 未给接口、错误码、性能阈值、设备范围或实现机制时不编造；可列条件或请求补充。技术方案是可选增强依据，不能阻断 PRD-only 使用。
- 每条测试条件至少关联一个用例，或者列明覆盖缺口、原因及补充依据。条件映射覆盖不等于测试充分性，更不等于执行通过。

## 设计不同类型与不同层级

按 `references/test-design.md` 选择适用类型：功能正常、边界、异常输入/失败、权限、安全防护、接口契约、状态流转、兼容、可访问性、性能、可靠性/恢复、回归、用户验收。

将三类概念分开：

- **类型**说明验证什么，如边界或权限。
- **层级**说明在哪里验证，如单元、集成、系统或验收；PRD 不足以推断单元边界时选系统或待分配。
- **方法**说明如何选数据，如等价类、边界值、决策表、状态迁移、成对组合或场景。不是每个用例都套全套方法。

优先验证高风险核心功能、权限与异常恢复，再补长尾；优先级写理由，不能按类型默认全部 P0。测试数据具体、匿名、可准备，环境和账号角色由授权测试范围确定；未知枚举、阈值或真实账户保留待确认，不编私人信息。

## 每条用例都能执行和判断

稳定编号 `TC-...`，写出标题、需求和测试条件引用、类型/层级/方法、优先级及理由、前提、数据、步骤、每步预期、用例级结果断言、清理和自动化建议。

- 每一步有操作和可观察预期，结果说明页面/响应/状态/数据如何核对，不能只写“正常”“功能可用”。
- 正向、负向、边界和组合场景依据同一规则；原条件是 `<` 不能润色为 `≤`，否定、模态、时间与单位保真。
- 依赖未确认规则时将 `definition_status` 设待确认，不能写成确定验收；数据和预期里的缺口写明，缺标准的用例不能算可执行覆盖。
- 自动化建议分“可自动化／需人工／待评估”，说明理由，生成文档不等于已经实现测试脚本。
- 初始 `execution_status` 一律“未执行”。本技能不自动连接产品、发送请求、压测、破坏数据或开展攻击。安全用例仅设计合法防护验证，必须隔离环境和必要授权，不含越界利用方案。

## 核验、版本交接与交付

先结构检查，再人工对照 PRD 检查规则等价、类型适用、断言可观察、缺口不被隐藏、无近义重复、风险优先级有依据。统计由明细现算，不能虚报“全覆盖”；按测试条件映射分别统计可执行、待确认和缺口，状态不等于执行结论。

有 Python 时：

```bash
python3 <技能目录>/scripts/cases.py check <test-cases.json>
python3 <技能目录>/scripts/cases.py render <test-cases.json> --output <test-cases.md>
```

替换占位路径并引用含空格路径；Windows 可用 `python`。渲染默认拒绝覆盖，只有更新本次产物时显式 `--force`。命令不执行产品测试、代码或文档内操作。

端到端时登记 `test_cases` 到同任务清单，绑定实际读取的 PRD 摘要；共享脚本 `register --role test_cases --file test-cases.json --producer test-case-design`，状态沿用套件文档。开发技能可自动读该已登记文件，映射到实现验证；生成新 PRD 后旧用例必须重新评估，不静默沿用。无共享脚本时记录输入摘要、任务与用例路径供下一阶段核验。

交付完整 JSON、易读文档及依据/覆盖/缺口说明，提供路径和打开方式。文字用平实中文，保持术语、字段、数字、条件和预期，不用套话掩盖待确认项。清楚说明仅完成用例设计和校验、未执行产品测试，不自动提交、推送、部署或改变产品代码。
