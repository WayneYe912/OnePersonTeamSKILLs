# 图文与阅读规范

## 图各自回答一个问题

- 主流程图：用户如何完成任务，系统何时判断条件，失败后如何恢复？
- 状态迁移图：哪些事件允许改变状态，回退条件是什么？
- 角色关系图：谁能看、谁能改、数据流向哪里？
- 低保真界面示意：入口、字段、操作和反馈在哪里？

根据需求选择，默认主流程加另一种互补图。仅有卡片配色或文字箭头不算完成图形。图的目的不是占版面。

## 图文使用同一份事实

先建立节点和关系数据，再渲染。用需求编号关联图文；新发现的分支先写回需求，再改图。输入顺序不是业务关系，连线必须显式定义。

图、节点和连线分别标明确认状态。整体“建议”不能掩盖节点原本“已确认”的事实，也不能把某个建议节点暗示成已定方案。

不确定的权限、阈值和默认值保留“待确认”。示意截图不能暗示用户提供了真实 UI；示例输入不能当统计数据。

## 默认视觉语言

面向评审，重视扫描和定位：浅底深字，以蓝色标已确认、棕色标建议、红色标待确认，并同时显示文字标记，不能只靠颜色。

正文桌面约 16px，行高 1.7；主要说明不少于 14px。内容宽度控制在适宜阅读的范围。章节用内容命名，稳定需求编号用于跳读，目录链接真实可用。

图与对应段落紧邻，标题在上，读图说明在下。低保真界面用区域、输入显示和操作文字，明确无交互；真正的链接才做可点击外观。

## 窄屏与打印

- 普通段落和需求条目改为单列，长字串换行。
- 图不缩成蚂蚁字；复杂连线可在标明的横向滚动容器内保持原字号。优先拆成更小的图，而不是丢分支。
- 使用 `viewBox`、合理间距和换行测算；图中 label 的长度与节点高度必须匹配。
- 打印隐藏目录和纯交互提示，保留标题、状态、编号、图和来源。长内容允许跨页，短图可保持完整；不用整章禁止跨页导致巨幅留白。
- HTML 内联 CSS 与 SVG，关闭 JavaScript、断网仍可读。不用 CDN 字体、在线图表引擎和远程图片。

## 图形复杂度

内置流程布局按节点纵向排列，连线逐条分配右侧路线，适合少量节点和分支。复杂泳道、稠密状态机和大流程必须拆分或由 Agent 编写更合适的确定性 SVG，不能硬塞进默认布局。

长标签先精准表达，不为缩短而删条件。图中引用需求 id，正文保留完整规则。需要拆图时每张图写明范围和跨图连接条件。

## 交付前观察

实际浏览器或宿主渲染器检查桌面与窄屏：首页、主流程分支、需求条目、界面示意、来源和末尾。

查箭头方向、线与文字是否相碰、标签是否溢出、未确认状态是否清楚、目录跳转是否定位正确。查看打印预览，至少抽查首页、一个跨页内容和末页。

脚本成功和文件存在不能代替视觉观察。环境不能截图或打印时，如实说明未验证层，不声称“全部通过”。
